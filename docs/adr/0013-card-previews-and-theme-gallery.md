# 卡片预览图：screenshots 上卡（主题画廊 + 缩略条）、卡面轻确认与图片多线路回退

DESIGN §2.6/Q44（ADR-0004 时代定稿）曾裁定「卡片瘦身：能力披露、截图、安装命令全部迁出卡片」「缩略图本机直连原图，不引第三方代理服务」——其语境是文字卡密度优先、截图属详情层信息。2026-10-05 主人提出参照 dsh-market 主题页形态上预览图（需求原文：参考其主题页做法把缩略图显示出来、不设计弹出卡片即可安装）。grill 四轮核对事实后修正了两个前提：①上游 awesome-dsh-plugin 目录本就携带作者维护的 `screenshots` 字段（153 款主题中 68 款有人工图），dsh-m 的社区适配层早已透传、详情 Modal 早已渲染——「上卡」是纯展示层工作，不构成数据管道工程；②dsh-market 主题页并非「无弹窗直装」——卡面安装按钮打开的是轻确认弹窗，真正的差异是 dsh-m 要求先开全量详情 Modal。同批核实：dsh-market 自己的普通插件页也只在「有人工图」时显示 ≤3 张横条缩略，16:10 大封面画廊是主题类目专属——「全市场图片化」被其自身形态反证。克隆实现不含图片线路改写，多线路回退为本计划新决策。

我们决定（2026-10-05，grill 四轮 Q1–Q7 + 实施计划评审两轮 9 项闭环；实施计划 `docs/plans/2026-10-05-theme-gallery-previews-implementation-plan.md`）：

1. **社区 screenshots 上卡，两形态**：社区区「主题与外观」分类（slug `theme`）浏览态整网格切换为画廊卡（16:10 封面 = 首图、多图张数角标、灯箱，页大小 16 且画廊态隐藏筛选页大小组）；其余条目维持文字卡，仅在 `screenshots` 非空时追加 ≤3 张横条缩略（无图卡片外观零变化）。收藏区主题条目用画廊卡（与 dsh-market 收藏页同款），其余文字卡；搜索态恒文字卡。不做全市场图片化、不为无图卡片造「暂无预览」占位（画廊卡内占位除外——那里占位有语义）。
2. **精选清单 schema 增补可选 `screenshots: string[]`**（≤8 项、每项 HTTPS ≤2048 无 userinfo、host 白名单 `github.com`/`*.githubusercontent.com` 与客户端消费端同语义、去重、允许空数组）。registry.json 数据不随本次变更（截图由主人手工补），发布纪律沿 §2.7：先发 dsh-m 新版、再推 registry @main。
3. **卡面轻确认安装**：文字卡与画廊卡 footer 提供安装按钮 → 轻确认弹窗（名称、描述、截图条、社区条目来源提示、弃用警告）→ 确认后才进入既有 `doInstall` 链路——peer 兼容预检拦截（compatConfirm 确认块）、装后守卫、操作记录、进度与终态展示全部不动；点击卡片本体仍开全量详情 Modal，能力披露/红线保持「仅详情层、默认收起」不变（Q44 该半边不放宽）。不做真·零确认直装。
4. **图片线路多线路回退**：`raw.githubusercontent.com/<owner>/<repo>/(HEAD|…)/<path>` 形态的图优先改写为 `cdn.jsdelivr.net/gh/<owner>/<repo>@HEAD/<path>`，img onError 逐候选回退原 URL；README 文本抓取同链路。不经任何第三方图像处理/缩放代理服务（weserv 类）——修订 §2.6「本机直连原图、不引第三方代理」为「多线路回退、不引第三方图像处理代理」。附证：`cdn.jsdelivr.net/gh/iasiv5/dsh-m@HEAD/package.json` 2026-10-05 实测 HTTP 200（jsDelivr 对仓库路径的 `@HEAD` 分发可用）。
5. **README 抽图兜底（瘦身版）**：仅画廊卡、卡片临近视口（IntersectionObserver 200px）才触发、每条目会话级内存缓存、纯语义打分（排除 badge/logo/avatar/icon/`.svg`，偏好 screenshots/preview/docs 路径；**无几何探针**——克隆实现的探针依赖其缩放代理，本方案无代理故不做）、README 正文 256KB 上限（content-length 预检 + 边读边限双保险）、8s 超时、失败静默降级为「暂无预览」占位。
6. **交付与治理**：版本 0.9.34；热部署 desktop profile 供主人实测后再议发布。术语（预览图/缩略条/画廊视图/轻确认安装/线路改写）入 GLOSSARY。

## Consequences

- **对既有裁决的显式修订**：Q44「截图仅详情层」的截图半边就此废止（能力披露/红线半边不动）；§2.6 技术默认件「直连原图、不引第三方代理」改述为「多线路回退、不经第三方图像处理代理」。DESIGN §2.2/§2.3/§2.5/§2.6/§2.7 同步修订。
- **数据与代码边界**：core 层只动 `registry.ts`（schema）；`community-adapter.ts`/`market.ts` 零改动（`toMarketItem` 纯展开自动透传新字段）。精选条目暂无截图数据属预期，字段空缺 = 不显示。
- **性能与流量**：缩略图无服务端缩放（原图直出，单张 1–2MB 量级），靠三层懒加载 + 视口门控限并发；README 兜底每条目每会话至多一次抓取。已知代价如实声明：兜底卡有「正在查找预览…」弹入延迟；语义打分偶发抽到非产品图；作者无法 opt-out 兜底（生态惯例，与克隆一致）。
- **可用性**：jsDelivr 国内可达性有波动史，回退链 raw 直连兜底；宿主侧 `/dshm/img` 镜像路由（gh-proxy 类镜像表，克隆对 README 文本有先例）列为 v1.1 观察项，本期不做。
- **non-goals**：全市场图片卡、无图占位常态化、零确认安装、几何探针、图片缩放代理、精选/社区之外的第四数据源。
