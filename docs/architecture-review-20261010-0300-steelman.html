这一轮多做了什么：钢人过滤

第一轮（已废弃的排序）

三路子代理 + 主审实测，按架构摩擦排出 9 张卡。排序混杂了两类证据：实测且会被感知的（事件循环阻塞、镜像机秒级等待）与推断且无人感知的（渲染重建次数、RPC 次数、对象分配）。

钢人裁决

对每张卡构造现状的最强辩护——「单用户宿主无人抱怨」「这套代码对缓存有伤疤」「重算是最简单的正确性纪律」「预加载是特性不是浪费」——然后看候选还站不站得住。辩护失败的卡出局，辩护成功的卡被迫换更硬的地基。

幸存者的共同点

每张都能回答「谁、在什么场景、痛多少毫秒」：市场每次交互阻塞宿主事件循环 65–400ms；镜像机器每次装机 happy path 白等 ~10s；收藏检查每条付一次零收益的探测扇出。出局项全部答不上这个问题。

Problem：GLOSSARY 定义了「合并市场」，但没有任何 module 拥有它——装配逻辑内联在 communityOutcome 里，每个请求从四个 module 的输出现场重组一遍。search-relevance.ts:11 自述的「性能护栏」WeakMap 因目录适配层每请求重建条目对象而跨请求永不命中；现成的内存快照 RegistryController.loaded 热路径从不消费——cache far from consumer。

Solution：一个进程内物化 module 拥有 load→adapt→merge→索引→预归一化字段，按目录 version + registry 代 keyed。第一刀就是首轮 C2（评分单遍化，market.ts:781-795 的两遍 relevanceScore 合一）——它已折入本卡作为起步切面。market.ts 瘦身为查询+探测编排，market↔community 的 import 环随之消解。

  • leverage：一个 interface，四个消费点
  • locality：合并规则变更只动一处
  • 安装路径 4,400 条重 adapt 找一个 id（market.ts:1813/1832）免费消失
  • 测试经 MarketDeps 注入计数：两次相同调用，第二次 loadRegistry/fetchCommunityCatalog 必须为 0
钢人后的地基（为什么 ADR-0006 的伤疤不适用）：0006 出事的是 latest 探测值——真值在远端、本地无失效信号；本卡物化的是本地文件的派生数据，失效键是确定性的文件身份（registry cacheKey+fetchedAt、目录 version、profile、namespace），目录 version-pin 文件名本就不可变（catalog-{version}.json）。探测值缓存 ≠ 派生数据 memo。ADR-0003 运行时合并语义、ADR-0006 内存制度、ADR-0008/0013 两段加载与探测模式全部不动——两段加载第一段只是不再重付管线。

sequenceDiagram participant T as 登记步骤 participant P as packument 访问器（deep） participant L as withFileLock participant N as npm registry T->>P: times(pkg)（锁外） P->>P: TTL 缓存命中? P->>N: 未命中才取（route-aware 单飞） T->>L: acquire L->>L: 纯 fs：读策略→写排除条目 L-->>T: release（毫秒级）

Problem：「registry 元数据」没有 owning module——三个 adapter 各自取、各自解释、各自缓存（或没有）。登记（Register）只为读一个发布时戳，却在官方文件锁内发起 8MiB 级网络取，把网络腿的墙钟直接加进每次装机的关键路径。

Solution：一个 route-aware packument 访问器（latest/version/times/warm 共享一个 TTL 缓存，键 pkg+registry，single-flight）；登记只把 fs 写留锁内，网络腿全部出锁。

  • 镜像机器装机 −~10s 纯等待
  • B3 重试的第二次全量取并入缓存
  • 锁持有回归纯 fs 毫秒级（次要红利）
  • 锁竞争测试断言锁内零网络即可测
钢人修正：原卡以「锁竞争串行化写者」为主要论据——被驳（单用户点不出并发写，竞争罕见）。存活腿是网络墙钟：happy path 秒级白等是实测会被感知的。ADR-0009 登记语义逐字不动；ADR-0012 读分类路由照旧——访问器是它的消费端不是替代品。

Top recommendation

C1 · 合并市场物化 —— 钢人之后反而更硬的一张

性能问题的架构根源只有一个：领域概念「合并市场（Merged Market）」在 GLOSSARY 里有名，在代码里无主。每次请求重付 5MB 解析 + 4,400 条 adapt + 全量 merge（实测 65–180ms，搜索再加 330ms 冷评分），而且是同步阻塞宿主事件循环——市场每翻一页，整个 DSH 宿主的对话流与工具调用停摆。物化 module 一处落子，同时吃掉数据通路五个摩擦点与安装路径的重复 adapt，让 search-relevance 的 WeakMap 护栏第一次真正跨请求生效（40×），并消解 market↔community import 环。钢人逼出的关键澄清：ADR-0006 否决的是探测值缓存（真值在远端），本卡物化的是本地文件的派生数据（失效键 = 确定性文件身份）——两类东西，伤疤不遗传。

攻击顺序：C3 收藏 cache-only + 零增量守卫（当天可合）→ C1（旗舰；第一刀 = 评分单遍化）→ C2 packument 访问器（网络腿）。
