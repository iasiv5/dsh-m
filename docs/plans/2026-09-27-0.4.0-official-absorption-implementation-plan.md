# dsh-m 0.4.0 官方能力吸收实施计划

## 目标

一个 `0.4.0` 版本吸收 DSH 0.1.7-rc.2 官方插件管理的六项能力（2026-09-27 grilling 定稿）：

1. **开关**：已装插件运行状态可逆切换，委派官方 pluginManager 服务优先、loader 直操作降级（ADR-0001）
2. **运行相位徽标**：已装卡显示 loader fiber 相位（active/failed/pending/…）
3. **保护名单**：开关与卸载拒绝 `dsh-m` 自身与官方命脉包
4. **精确构建放行**：needs-builds 后按 pending 名单逐键放行，全量放行降为兜底（ADR-0002）
5. **peer 兼容预检**：install/upgrade 前对 `@deepseek-ai/dsh(-*)` peers 做 semver 校验；registry 条目新增 `verified` 实测清单
6. **bundle 身份验证 + 元数据源竞速**：装后验证补丁层存在性并警告；npmjs/npmmirror ping 竞速选择元数据读取源

## 架构快照

- **开关读写分离**（ADR-0001）：读路径始终自读 loader entries（`ctx.loader.entries()`，经 live-plugin.ts 既有绑定）+ 包内 `cordis.patch.yml` 行枚举 + profile `dsh.profile.bundles` 三方合成；写路径运行时探测 `ctx.get('pluginManager')`，服务在→委派 `setPluginEnabled`/`setBundleEnabled`（行/整层语义、保护判定、hmr 活体重组全部白拿），服务缺席→loader `entry.update()` 直操作 + 锁内保注释 YAML 编辑（行级即时生效）或 bundles 数组编辑（restart-required）。探测按服务存在性，不判 DSH 版本号。
- **粒度自动路由**：读包内补丁层，单 insert 行且无配置补丁行 → 行开关；多行或不可解析 → bundle 开关。对外 UI 只呈现一个开关。
- **开关不经 Profile 变更事务**：单文件轻量编辑，但必须持官方同款锁（`withFileLock(<profile>/package.json)`，锁文件 `package.json.lock`，`wx` 独占）防与官方 UI 并发丢更新。
- **预检与放行各就其位**：peer 预检在事务外（metadata 解析阶段）；精确构建放行在 adapter 的 add ladder 内（needs-builds 拦截点，`makeAddViaLadder`），事务层只透传 RunnerOutcome 的放行结果；bundle 身份验证在事务 verify 阶段（只警告不回滚）。
- CLI 无宿主进程：`dshm toggle` 走文件级编辑（restart-required）；GUI/agent 走宿主内活体路径。

## 全局约束

- Node `>=22`；DSH 多代兼容原则：**按 API/服务形态运行时探测，不判 DSH 版本号**（settings 兼容层、ADR-0001 同一传统）
- 新依赖锁精确版本：`yaml`、`semver`、`@deepseek-ai/dsh-atomic-write@0.1.7-rc.2`（npm `latest` dist-tag 陈旧，用 `next` 通道精确版，know-how 006 教训）
- 命名规则：领域术语以根 `CONTEXT.md` 六词条为准（开关/行覆盖/Bundle 选择/运行相位/委派降级/实测版本清单）；API method 名 `set-enabled`；Config 字段 `probeEnabled`/`probeTimeoutMs`/`probeCacheTtlMin`
- 文案规则：i18n zh/en 双语齐全；构建放行 notify 必须列出放行的包名；兼容预检失败在 GUI 弹确认、agent 回结构化结果等用户决定、CLI 用 `--force` 跳过；github 源不预检，结果中明示
- 保护名单作用于**开关与卸载**，不拦升级（升级是 dsh-m 核心价值）；委派路径信任官方 `readOnlyReason`，降级路径用硬编码名单——名单**逐字镜像官方 16 项全集**（锚点 `dsh-plugin-manager@0.1.7-rc.2 lib/index.js` `protectedModules`），每次 DSH 升级后 diff 官方名单同步（进 know-how 008 升级必查口径，由主人在 workspace 侧维护）
- 兼容预检语义照官方 `evaluatePluginCompatibility`：只检 `@deepseek-ai/dsh` 与 `@deepseek-ai/dsh-*`；`workspace:^`/`workspace:~`/`workspace:*` 视为当前运行时版本；semver `includePrerelease: true`；不做豁免机制（确认/`--force` 即通道）
- `verified` 是实测声明：只展示与收录质量提示，**不做安装拦截依据**
- 开关编辑 `cordis.patch.yml` 必须保注释（官方 `writePluginEnabled` 同款 findLast + `disabled` 键语义）；启用写显式 `disabled: false`

### Task 5: toggle.ts — 委派/降级写编排

- 目标：一个入口完成保护门 → 粒度路由 → 委派或锁内降级编辑 → 活体应用
- Files: Create `src/core/toggle.ts`、`tests/toggle.test.mjs`
- 接口契约：
  - Consumes: `isSingleRowPlugin`/`planRowOverride`（Task 2）、`PROTECTED_MODULES`（Task 4）、`listInstalledPlugins`（installed.ts，提供 patchRows 与在装判定）、`withFileLock`（`@deepseek-ai/dsh-atomic-write`，锁 `<profile>/package.json`）、`setLivePluginDisabled`（live-plugin.ts）
  - Produces:
    - `interface ToggleResult { pkg: string; enabled: boolean; applied: 'live' | 'restart-required'; via: 'delegate' | 'fallback'; warnings: string[] }`
    - `interface PluginManagerLike { listPlugins(): Promise<Array<{ entryId: string; moduleName: string; enabled: boolean; fiberPhase?: string | null; readOnlyReason?: 'management-required' | 'unaddressable' }>>; setPluginEnabled(id: string, enabled: boolean): Promise<unknown>; setBundleEnabled(name: string, enabled: boolean): Promise<unknown> }`（官方返回值为 change() 富结果，鸭子读 `application`/`warnings` 字段，不建类型依赖）
