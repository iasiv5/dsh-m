## 三、git 状态「勘误」：不成立，但处置一致

porcelain 格式为 XY 两列：**X = index（staged），Y = worktree（unstaged）**；`M ` 是已暂存修改，` M` 才是未暂存。我上轮评审时的快照为 `M `/`A `（X 列，已暂存）；本轮复核的当前快照**仍是**全 X 列（`M ` + `A `×4，含已被执行 agent stage 进去的评审报告），无 `??`、无 Y 列改动。执行 agent 观察到的「M（未暂存）+ ??」与其编辑 Rev2 期间的瞬态（编辑已暂存文件产生 Y 列改动；评审报告在 add 前为 `??`）或列读法有关——**两个稳定时点的证据都不支持该勘误，原评审表述在观察时点是准确的**。此点不影响任何结论（处置同为 docs commit 先行），仅按老规矩修正事实记录。
