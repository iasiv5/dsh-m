# 需求文档 · ZoneChips 折叠测量缺陷修复（视觉裁剪方案）

- 日期：2026-10-08
- 状态：待评审
- 目标版本：0.9.53
- 关联：0.9.52（哨兵移位，`docs/CHANGELOG.md` 中文区 0.9.52 条目）

## 1. 背景（事实）

dsh-m 市场面板头部「分类 chips 行」（`ZoneChips` 组件，`src/client/main.jsx:902-982`）具备
「两行折叠 + 实测裁剪」能力：渲染后用 `useLayoutEffect` 逐 chip 按 `offsetTop` 分组数行，
把前两行放不下的分类折叠为「+N」按钮（`main.jsx:926-944`）。

0.9.52 上线后的端到端验证发现一个**既有**时序缺陷（该测量代码自 0.7.0 Task 10 引入后未变，
0.9.52 仅改动吸顶哨兵 DOM 位置，不参与 fit 计算）：

### 1.1 现象

新浏览器 profile（localStorage 为空）首次打开市场面板，社区区分类行以
「全部 + 3 颗分类 + +20」的**单行折叠**形态驻留；正确形态应为两行展开（约 17~18 颗 + N）。
同会话内刷新页面后重开面板，显示恢复正确。

### 1.2 复现与证据（2026-10-07/08 无头 Chromium 实验）

- 冷 profile 首开：`shown` 时间线 1 → 5，之后冻结；`fontsStatus` 全程 `"loaded"`、
  `fonts.ready` 0ms、chip 宽度恒定——**排除字体加载因素**。
- 同会话 reload 后重开：显示 18 颗（两行预算），正确。
- 算术对账：社区区分类总数 23；`fit={rows2:3}` ⇔ 渲染「全部 + 3 分类 + +20」（3+20=23）✓。

### 1.3 根因（机制描述）

1. 面板首挂载时市场数据未到达，`chips.length = 0`，列表仅常驻「全部」一颗；
   测量 effect（`main.jsx:926-944`）在**空列表**上测得 `fit = {rows2:1, rows1:1}`。
2. 市场数据异步到达后 `chips.length` 0→23，依赖变化使 effect 重跑；
   **但 effect 跑在重渲染之后**，此时 DOM 已按旧预算 `budget=min(1,23)=1` 折叠，
   实际只渲染「全部 + 首分类 + +22」共 3 元素（全在一行）。
3. effect 只能"发现"这 3 颗 → `fit={rows2:3}`；再渲染 `全部 + 3 分类 + +20` 后，
   依赖（`chips.length/expanded/zone`）不再变化，**effect 永不重跑** → 冻结。
4. `market-snapshot.js` 的 localStorage 快照使暖会话首挂载即有全量数据，
   一次测准——这解释了为何日常使用（含 0.7.0 以来所有历史版本）从未暴露。

### 1.4 姊妹问题

测量 effect 依赖不含宽度信号：窗口缩放导致行容量变化时同样不重测，
`+N` 计数与实际可容纳数脱节（`main.jsx:926-944` 依赖数组）。

## 2. 目标

- **G1** 冷存储首访（无快照）时，分类行按真实宽度正确显示两行 + 正确的 `+N` 计数。
- **G2** 数据异步到达（0→23 颗）过程中及到达后，折叠状态始终正确，无错误冻结。
- **G3** 保持既有交互语义不回归：
  - 滚动吸顶自动收为一行、回滚恢复两行（0.9.52 哨兵链路，`main.jsx:945-951`）；
  - `+N` 展开 / `⌃` 收起；激活分类被裁剪时自动展开；
    「用户手动收起后，同一激活分类不再自动展开」（autoRef 语义，`main.jsx:909-925`）；
  - 0 计数分类降透明（`main.jsx:958-960`）；
  - 「筛选」触发器折叠态下仍可见可点（现状 in-flow 行尾，`main.jsx:978` + `main.jsx:1550+`）。
- **G4** 顺带修复姊妹问题：容器宽度变化后 `+N` 与裁剪即时重算。
- **G5** 不回归：全量既有测试（当前 1200 例）零新增失败；typecheck 零错误；
  社区/精选两分区、深浅主题均正常。

## 3. 非目标

- 不改分类数据层 `zoneChips()`（`src/client/market-state.js:227-257`）；
- 不改「筛选」弹层功能本身（仅触发器位置/可见性策略）；
- 不引入列表虚拟化（分类总数 ≤ 24，无性能压力）；
- 不处理面板开合动画（面板无动画，`main.jsx:280` CSS 无 transition）。

## 4. 验收标准（V1–V9）

| # | 场景 | 通过标准 |
|---|---|---|
| V1 | 冷 localStorage 首开面板（复现 §1.1） | 分类行两行展开，`+N` 计数与真实裁剪一致 |

| V3 | 拖拽改变窗口宽度（多档：>920 / ~700 / ~500px） | 裁剪与 `+N` 即时重算，无冻结 |

| V5 | `+N` 展开 → `⌃`/选分类收起；激活分类落在裁剪区 | 语义与现状一致；自动展开与 autoRef 行为一致 |
| V6 | 「筛选」触发器折叠态可见、可点，弹层定位正常 | 与现状交互一致 |
| V7 | 深色/浅色主题切换 | 覆盖徽章/钉住元素可读性正常 |
